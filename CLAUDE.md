# CLAUDE.md: Kiver Build pages

Read SPEC.md before writing code. It is the contract. This file is the short list you keep in your head.

## What this repo is
Five public web pages, one per house model (Kiver 64, 96, 96 Pro, 144 Pro, 144 Max), each explaining how the house is assembled in 30 working days (45 for the Max). Every page has the same skeleton: due diligence (before Day 1), a Gantt with a day scrubber, a three.js scene that builds itself as the scrubber moves (the 64 has two scenes, factory and site), a day panel, options and resale, the shared partners strip, the shared per m² cost table, a time-lapse gallery of completed builds, and one WhatsApp call to action. Bilingual PT/EN. Static build, embedded by iframe on kiver.org first, moved to igorbuildshouses.com later without code changes. The WhatsApp assistant in `bot/` is a separate service; see docs/SALES.md.

## Stack (decided, do not relitigate)
- Vite + React 18 + TypeScript + three (npm, pinned; no CDN scripts in the build)
- Static output in `dist/`, hash routing, deployed on Cloudflare Pages (docs/DEPLOY.md) with no server
- No UI framework. Plain CSS modules or a single `theme.css` with variables from `data/shared/brand.json`
- No analytics. The only third-party embeds are YouTube time-lapses from `timelapses.json`. No live camera feed on the site, ever (it goes to the investors' private WhatsApp group).

## Data is the product
- Everything a visitor reads comes from `data/`. Components never hardcode model facts, partner names, prices or dates.
- `data/models/*.json` are generated by `scripts/gen_schedules.py` and `data/shared/cta.json` by `scripts/gen_sales.py`. Change the Python, re-run, commit both. Do not hand-edit generated JSON. `bot/flow.json` and `bot/faq/*.json` are hand-maintained sources; edit them directly.
- Shared blocks (`data/shared/*.json`) render identically on all five pages.
- Every user-facing string is `{pt, en}` in data or a key in `data/i18n/ui.json`. No bare strings in JSX.
- Anything marked `confirmed: false`, `verify: true` or `value: null` renders with the "to be confirmed" treatment; a null logo renders a monogram. Never invent a name, logo, price or date to fill a gap. Ask.

## Conventions
- Components in `src/components`, one folder per component, index export, colocated CSS
- Three.js scene builders in `src/scene/` as pure functions `(params) => { group, stepGroups: Map<stepId, THREE.Group> }`. No React inside builders.
- Single source of truth for the selected day: `useDayStore` (zustand or a tiny context). Gantt, scene, day panel and URL `?day=` all read from it.
- Mobile first. The scrubber must be usable with a thumb on a 380 px screen.
- Accessibility: every control keyboard-reachable; the Gantt has an equivalent list view for screen readers.
- Copy style in both languages: short sentences, no em dashes, numbers with units (m², R$). Brand is written "Kiver Build" and the byline is "Kiver", never the legal surname.
- Commit small. One phase from SPEC §17 per PR. Commit message starts with the phase number, e.g. `P3: gantt scrubber`.

## Ask before you
- change a field name in any `data/` schema
- add a dependency beyond react, react-dom, three, zustand, vite, typescript, vitest
- publish anything under a name other than "Kiver Build"
- show a house price, a return, a ticket or an investment term anywhere, in any language (rates per m² are public; everything else is private, after identification)
- embed a live stream, or put the word "sprint" or a 30-day claim on the Max page
